Reservation confirmation: analysis and design

Author: José Antonio Gallegos Carvallo

This sample was created from scratch for the portfolio. It contains no enterprise data, code or documents.

1. Functional requirement

Prevent a reservation from being confirmed if its date is missing or earlier than the minimum allowed date. Preserve the existing availability check before saving.

2. Fictional evidence

101: Event 'Confirmar'
102:    ValidarDisponibilidad()
103:    GuardarReserva()
104: Endevent

The existing operation checks availability and then saves the reservation. Identifiers are retained from the fictional Spanish example.

3. Acceptance scenarios

  • Missing date: show a message and prevent saving.
  • Date before the minimum: show a message and prevent saving.
  • Date on or after the minimum: continue with the existing availability check and save behavior.

4. Proposed design

Event 'Confirmar' // reference: 101
   If &FechaReserva.IsEmpty() Or &FechaReserva < &FechaMinima // ADD
      Msg('Select a valid date.') // ADD
      Return // ADD
   Endif // ADD
   ValidarDisponibilidad() // reference: 102
   GuardarReserva() // reference: 103
Endevent // reference: 104
